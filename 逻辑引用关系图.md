# 逻辑引用关系图

> 描述 w3ex 各层之间的依赖方向与调用关系。**依赖只允许自上而下**（UI → API → 业务层 → Provider → 外部），任何反向引用都是架构错误。

## 2. 关键调用链（垂直切片：用户在 /trade 买 $1000 ETH）

```
app/trade/page.tsx
  → lib/api.ts getQuote("buy","ETH","1000")
    → GET /api/v1/trade/quote?side=buy&asset=ETH&amount=1000
      → routes/trade.py（参数校验）
        → execution/router.py ExecutionRouter.get_quote
          → CompositeExecutionProvider（rich）
            → asyncio.gather 并发：
               ├─ BinanceExecutionProvider.get_quote
               │    → http.fetch_json(SDEPTH)  ← data-api.binance.vision
               │    → depth_walk 逐档吃单 → avg_price/滑点/0.1% taker
               ├─ JupiterExecutionProvider.get_quote
               │    → /v6/quote 真实路由 → priceImpact/0.04%/gas
               └─ HyperliquidExecutionProvider.get_quote
                    → /info allMids → 0.05% 估计滑点/0.045%
            → 全败 → mock 兜底（离线可演示）
          → best_route_index = argmin(total_cost_usd)
          → trade_quotes 落库（routes JSON 快照）
      ← {quote_id, routes[], best_route_index, expires_at, status:"pending"}
  ← UI 渲染报价表，用户单选 route → 点击 Confirm
  → postConfirm(quote_id, route_index)
    → POST /api/v1/trade/confirm
      → 状态机校验（pending？未过期？未重复？否则 422/404）
      → paper fill → trades 落库 paper=true
  ← {status:"executed", paper:true, filled:{price, receive, fees_usd, total_cost_usd}}
  ← UI 显示 PAPER SIMULATED 结果面板
```

## 3. 契约同步链（改一处必须连改三处）

```
providers/base.py（canonical 结构定义）
   ↓ 实现
api/routes/*（响应形状，docs/05-api-contracts.md 为准）
   ↓ 消费
frontend/lib/api.ts（TS 类型 + fetcher）
   ↓ 渲染
app/* 页面
```

冒烟脚本 `w3ex_smoke.mjs` 同时断言两端形状——任何一层单独漂移都会在冒烟时暴露。

## 4. 横切关注点归属

| 关注点 | 归属文件 | 规则 |
|---|---|---|
| 金额精度 | 路由层边界 | 库内用 Decimal，出 API 一律 str（前端 Number() 解析） |
| 时间戳 | db/base.py utcnow | 全库 UTC naive，API 输出 isoformat |
| 缓存 | providers/http.py TTLCache | 只在 Provider 层缓存，业务层不缓存 |
| 错误降级 | providers/composite | ProviderUnavailable 只在此层被捕获 |
| 来源标注 | 各响应 sources 字段 | UI 必须展示「真实数据 / mock 模拟」 |
| 配置 | config.py（W3EX_ 前缀，读 backend/.env） | 代码不硬编码 URL，镜像切换靠 env |

## 5. 禁止的依赖（架构红线）

1. routes 直接 import 具体 Provider（必须走 deps 注入的 bundle）；
2. frontend 直接调用外部 API（必须经 lib/api.ts）；
3. Provider 层 import intelligence/execution（数据层不感知业务）；
4. UI 隐藏 mock 来源（透明性原则）；
5. 任何绕过 confirm 状态机的执行路径。
